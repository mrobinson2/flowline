# v1.6.0: Every Menu Answer Drives Work — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Every option of every question in the sidebar changes the map (tasks, durations, gates, handoffs or waiting) in at least one realistic scenario, and a test fails the day one stops. Answers the user review of 2026-09-28 (`prompt-20260928a.txt`): Paved Road and Custom looked identical, Lifecycle stage / Runtime model / Generative AI / Selection facts changed nothing, and most identity, network and support options were recorded only.

**Diagnosis (measured, not guessed):** the engine is correct; the shipped sample's *content* is thin. About a third of the options drive no task; the "standard" and "custom" architecture routes produce the same task set; GenAI gates nothing and does not imply AI/ML; all four selection routes lead to one RFP task; six derived flags (`privateEndpoint`, `highAvailability`, `support24x7`, `performanceValidationRequired`, `formalDrTestRequired`, `pocRequired`) are read by nothing. Separately, the three elapsed cards follow the critical path only, so parallel work with slack moves excess/handoffs/gates/waiting but not end-to-end — that is correct and gets explained, not changed.

**Architecture:** data only — `data/scenario.data.js` (derivations, `implies`) and `data/process.data.js` (new conditional activities, multipliers, rewired conditions). No engine change. Mechanisms already present: activity `when`, `multipliers` (compound, factors < 1 allowed), `implies` (applied inside `schedule.build`), predecessor bridging over excluded steps.

## Global Constraints
- **The default map does not move:** default scenario keeps 39 activities, 198 days, and the identical metric signature (optimal, excess, handoffs, gates, waiting). Every new task and multiplier is gated on a non-default answer. Asserted.
- Existing presets may change (that is the point) — each change is intended and listed in the CHANGELOG.
- Durations are business days; owners, categories and waste types come from the existing taxonomy and team list; governance gates that must not be skipped are `canOverride: "governed"`.
- New steps join the graph where the work really sits (after the step that produces their input, before the step that consumes their output), so excluded steps bridge cleanly.

## Review Focus
1. **Coverage is real, not vacuous:** the test flips each option in the default AND in each preset / context scenario and requires a metric or task-set change in at least one — an option that only "passes" by removing the default value of a multi-select must also pass as an addition.
2. **Default invariance:** full metric signature, not just node count (a bridged excluded predecessor could add a phantom handoff).
3. **GenAI ⊇ AI:** every task the AI/ML answer adds is present under GenAI, plus more.
4. **Paved vs Custom differ at every service tier** (they were identical at Tier 0/1/2/tbd).
5. **Selection routes are distinguishable:** eval, rfp, rfi-rfp, eval-poc, rfp-poc, rfi-rfp-poc yield distinct task sets.
